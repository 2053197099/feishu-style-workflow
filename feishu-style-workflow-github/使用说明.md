# 飞书风格种子上传流程使用说明

这个仓库用于把飞书源多维表格里的风格种子图片，按字段一一对应上传到飞书收集表单，并在提交后自动复核结果总表。

流程特点：

- 从飞书 API 下载源表原始附件文件。
- 不使用截图、裁剪图、缩略图作为上传源。
- 提交前生成确认截图，必须人工确认后再提交。
- 提交后自动检查飞书提交成功页。
- 提交后自动读取结果总表 API 复核记录。
- 等结果总表界面稳定后再截图。
- 提交成功后自动清理本地临时图片。

## 目录结构

```text
.
├── feishu_style_workflow.js          # 主流程脚本
├── package.json                      # Node 依赖和命令
├── package-lock.json                 # 锁定依赖版本
├── .env.example                      # 环境变量示例，不含真实密钥
├── .gitignore                        # 忽略本地密钥、下载图片、运行产物
├── README.md                         # GitHub 简版说明
├── 使用说明.md                       # 中文详细说明
└── skills/
    └── feishu-style-workflow/
        └── SKILL.md                  # Codex 中文 Skill 提示词
```

运行时会生成 `.feishu-work/`，里面包含下载图片、确认截图、结果截图和临时 JSON。这个目录不会上传 GitHub。

## 环境要求

- Node.js 18 或更高版本
- Google Chrome 或 Microsoft Edge
- 飞书开放平台应用
- 飞书应用已开通并审批必要权限

需要的飞书权限包括：

- 查看多维表格
- 读取云空间文件
- 下载云空间文件

## 第一次安装

克隆仓库后进入目录：

```powershell
git clone https://github.com/你的用户名/你的仓库名.git
cd 你的仓库名
```

安装依赖：

```powershell
npm install
```

如果 PowerShell 提示 `npm.ps1 cannot be loaded`，用：

```powershell
npm.cmd install
```

## 配置飞书凭据

复制环境变量模板：

```powershell
Copy-Item .env.example .env
notepad .env
```

填写：

```text
FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxxx
FEISHU_APP_SECRET=your_app_secret_here
```

不要把 `.env` 上传 GitHub。仓库里的 `.gitignore` 已经忽略它。

也可以不创建 `.env`，直接在当前终端设置：

```powershell
$env:FEISHU_APP_ID='cli_xxxxxxxxxxxxxxxxx'
$env:FEISHU_APP_SECRET='your_app_secret_here'
```

## 标准使用流程

### 1. 提交前准备

用户给出源表序号后，先运行：

```powershell
node .\feishu_style_workflow.js prepare 12,13,15
```

脚本会：

- 读取源表当前视图。
- 按序号定位源表行。
- 下载 `人 / 动物 / 建筑 / 环境` 四个字段的原始附件。
- 生成源表行确认截图。
- 打开目标表单并填入：
  - 风格种子
  - person
  - animal
  - architecture
  - environment
  - 种子挖掘者：沐柒Moki
- 生成目标表单确认截图。
- 不提交。

确认截图位置：

```text
.feishu-work/confirm/
```

需要人工检查每一行是否一一对应。

### 2. 确认后提交

确认无误后，提交同一批序号：

```powershell
node .\feishu_style_workflow.js submit 12,13,15
```

脚本会：

- 重新填表。
- 点击提交。
- 检查是否出现提交成功。
- 检查是否还有 `必填` 错误。
- 读取结果总表 API，确认对应种子已经出现。
- 检查结果总表四个图片字段都存在。
- 检查 `种子挖掘者` 为 `沐柒Moki`。
- 打开结果总表页面。
- 等页面视觉稳定后截图。
- 清理本地临时下载图片和确认截图。

结果截图位置：

```text
.feishu-work/result_table_after_submit.png
```

### 3. 只复核，不提交

如果只想确认某些种子是否已经进入结果总表：

```powershell
node .\feishu_style_workflow.js verify 3522807328,468206440
```

### 4. 清理本地临时文件

如果某批 prepare 后不打算提交，可以手动清理：

```powershell
node .\feishu_style_workflow.js cleanup 12,13,15
```

## 字段对应关系

源表字段：

```text
风格种子
人
动物
建筑
环境
```

目标表单字段：

```text
风格种子或p（每周上限10个）
person
animal
architecture
environment
种子挖掘者
```

映射规则：

| 源表字段 | 目标字段 |
| --- | --- |
| 风格种子 | 风格种子或p（每周上限10个） |
| 人 | person |
| 动物 | animal |
| 建筑 | architecture |
| 环境 | environment |
| 固定值：沐柒Moki | 种子挖掘者 |

## 重要安全规则

必须遵守：

- 不要提交 `.env`。
- 不要提交 `.feishu-work/`。
- 不要提交下载到本地的图片。
- 不要把 `FEISHU_APP_SECRET` 写进代码或文档。
- 不要用截图当上传源。
- 不要跳过 `prepare` 直接 `submit`。
- 不要在截图和 API 无法对应时强行提交。

建议 GitHub 仓库设为 private，因为仓库中包含飞书表格链接、表单链接、app token、table id 和 view id。

## Codex Skill

中文 Skill 提示词在：

```text
skills/feishu-style-workflow/SKILL.md
```

在其他设备上使用 Codex 时，可以把这个 Skill 安装或复制到 Codex 的 skills 目录中。之后对 Codex 说类似：

```text
帮我上传源表序号 12、13、15，先生成确认图，不要提交
```

确认无误后再说：

```text
确定提交
```

Codex 应按 Skill 流程执行：先确认、后提交、再复核结果总表截图。

## 多设备使用

每台设备需要单独做一次：

1. 克隆 GitHub 仓库。
2. 运行 `npm install`。
3. 创建本机 `.env`。
4. 填写本机可用的 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。
5. 确认本机安装了 Chrome 或 Edge。

不要在设备之间通过 Git 同步 `.env` 和 `.feishu-work/`。

## 常见问题

### PowerShell 不能运行 npm

使用：

```powershell
npm.cmd install
```

或：

```powershell
npm.cmd run check
```

### 提示缺少 FEISHU_APP_ID 或 FEISHU_APP_SECRET

检查 `.env` 是否存在，或者当前终端是否设置了环境变量。

### 提交后仍显示必填

这表示飞书表单内部没有识别某个文本字段。脚本会把这次提交视为失败，不会清理现场文件。需要保留 `.feishu-work/` 用于排查。

### 结果总表查不到种子

可能原因：

- 提交没有真正成功。
- 结果总表视图排序或筛选变化。
- 飞书 API 延迟。
- 提交到了错误表单。

此时不要删除临时文件，先复核提交截图和 API 返回。
